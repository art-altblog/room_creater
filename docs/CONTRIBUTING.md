# Порядок работы с кодом

1. Каждое изменение связывается с реальной карточкой WEEEK и требованием ТЗ. В карточке указывают ветку, коммиты, результат проверки и фактический статус.
2. Рабочая ветка создаётся от актуальной `main`: `feature/TASK-XX-short-name`, `fix/BUG-XX-short-name` или `docs/TASK-XX-short-name`. `TASK-XX` заменяют кодом карточки либо её фактическим номером. Не приписывают коммитам старые даты и чужое авторство.
3. Коммит содержит код задачи и короткий результат, например `TASK-31: добавить масштабный план комнаты`. Для разных законченных шагов создают отдельные осмысленные коммиты.
4. После самопроверки автор открывает pull request в `main`. В описании указывает ссылку на WEEEK, связанные ФТ/НФТ, что изменено, как запустить и что проверено. Другой участник просматривает изменения и оставляет review; автор исправляет замечания.
5. Слияние выполняют после фактической проверки. Ссылку на принятый PR заносят в WEEEK. Нельзя отмечать код проверенным другим участником только на основании работы автора.
6. Перед коммитом проверяют `git status` и `git diff --check`. Пароли, токены, `.env`, личные данные и локальные базы не публикуют. `.gitignore` обновляют при появлении новых инструментов.

Для текущего статического прототипа проверка включает запуск по README, добавление и перемещение предмета, предупреждение об ошибке размеров и локальное сохранение/открытие. Серверное сохранение появится отдельной задачей и не должно приписываться этому PR.
